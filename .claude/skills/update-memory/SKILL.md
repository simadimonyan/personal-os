# update-memory — L-память агентов (L0→L4)

Самостоятельная системная команда Personal OS. Прогоняет полный цикл 5-уровневой памяти `L0→L1→L2→L3→L4`: линейные слои (факты → сцены → персона) + L4 семантический граф.

## ⚙️ Это уже работает само (2026-08-09)

Тот же конвейер запускается **автоматически при завершении сессии** (`/clear`, выход, resume) — хук `SessionEnd` отсоединяет `.claude/hooks/memory_update.py`. Руками команду звать нужно только чтобы прогнать **сейчас** или после правок скиллов.

| | Кто делает |
|---|---|
| Шаги 0, 1, 3, 4 (экспорт L0, индекс, граф, новые связи, файл-день лога L4) | сам скрипт, детерминированно |
| Шаг 0.5 (Telegram) и Шаг 2 (L1→L3, идиолект, ADR) | безголовый `claude --agent memory-extractor` |

Что важно знать при ручном прогоне:

- **Список сессий считается по журналу**, а не «по свежести»: `.claude/hooks/.memory-state.json` помнит обработанные файлы L0 (mtime+размер). Поэтому агенту не приходится жевать одно и то же, а пропущенный прогон ничего не теряет — сессии подберёт следующий.
- **Потолок 12 сессий на прогон** (`max_sessions_per_run`), остальные уходят в следующий.
- **Интервал 20 минут** между автопрогонами: два `/clear` подряд не запускают конвейер дважды. `--force` игнорирует интервал.
- **Новизна связей L4** считается против журнала уже записанных пар (`seen_pairs`) — иначе `brainstorm` каждый раз пишет в лог одни и те же верхние пары.
- Настройки — `.claude/hooks/memory_update.json` (`enabled`, `model`, `telegram_export`, интервалы). Журнал — `.claude/hooks/.memory-update.log`, последний результат — `memory_status.json` (о сбое доложит хук `SessionStart`).

```bash
python3 .claude/hooks/memory_update.py --dry      # что взял бы в работу
python3 .claude/hooks/memory_update.py --force    # прогнать сейчас
python3 .claude/hooks/memory_update.py --status   # чем кончился прошлый
```

Ниже — полный протокол: он остаётся источником правды (по нему собран скрипт) и выполняется вручную, когда автоконвейер выключен или упал.

### Шаг 0.5 — Telegram-диалоги из контекста

Если пользователь в текущем разговоре или в обрабатываемых сессиях **упоминает конкретный Telegram-чат или диалог с кем-то** («мой диалог с X», «чат Y», «переписка с Z») — этот диалог автоматически полностью экспортируется и фиксируется в Органоне, не дожидаясь отдельной просьбы:

```bash
# 1. Найти чат — СНАЧАЛА в базе чатов фермы, без выхода в Telegram
node ~/.claude/skills/telegram/driver.cjs db_chats '{"query":"<имя из упоминания>","limit":20}'
#    если в базе нет — только тогда живой список: get_dialogs '{"limit":100}'
# 2. Выгрузить историю ПОЛНОСТЬЮ одной командой — export_chat сам пагинирует
#    и качает медиа (фото, голосовые, кружки, видео, стикеры) в подпапку media/
node ~/.claude/skills/telegram/driver.cjs export_chat \
  '{"chat_id":"<id>","out_dir":"'"$VAULT"'/11 — Архив/Телеграм чаты/{имя-чата}"}'
# → {"file":"…/{YYYY-MM-DD} export.md","messages":N,"media":{"saved":…}}
```

Файл и frontmatter (`type: telegram-export`, chat, chat_id, date, messages, media, period) драйвер формирует сам —
вручную markdown не собирать. Полезные флаги: `"media":false` (только текст), `"limit":N` (последние N сообщений),
`"max_media_mb":N`. Экспорт идёт по сети и на больших чатах занимает минуты — прогресс печатается в stderr;
при обрыве просто перезапустить, уже скачанные медиа не тянутся повторно.

**Имя чата в отображаемом виде может не совпадать с именем человека** (ник, эмодзи, стилизованный шрифт) —
искать по `get_dialogs` не только по имени из упоминания, но и по username; если чат не находится — спросить у пользователя,
а не гадать. Найденное соответствие «человек → аккаунт» зафиксировать в памяти.

Экспортированные диалоги попадают в общий индекс на Шаге 1 и становятся доступны памяти и графу. Повторный экспорт того же чата — новым файлом с текущей датой (дифф истории), не перезаписью.

**Экспорт не складывается в архив молча — он разбирается.** Свежий экспорт (и любой другой `type: telegram-export`, попавший в прогон) читается на Шаге 2 как источник тега `[SOCIAL]`: **как Димитри общается с этим человеком**. Смотреть только его собственные сообщения (`out: true`), реплики собеседника — контекст. Что снимать: с кем и какие отношения (близкий / знакомый / деловой / продавец), регистр и дистанция, кто инициирует и кто закрывает разговор, чем открывает и чем заканчивает, как просит, отказывает, извиняется, благодарит, спорит, как реагирует на просьбу и на давление, сколько о себе открывает, подстраивается ли под манеру собеседника. Результат — рубрика **«Как общается с людьми»** в файле-дне идиолекта (`L3 Persona/Идиолект/идиолект {дата}.md`), подрубрика на человека, каждый пункт с дословной цитатой. Накопитель — `Идиолект/Идиолект — как общается с людьми.md`.

> 🔒 Переписка с живыми людьми — чувствительный материал. В память идут **паттерны общения Димитри с цитатой-примером**, а не пересказ чужой личной жизни и не то, что собеседник доверил лично.

### Шаг 2 — L-память L1→L4 (агент memory-extractor)

`memory-extractor` сам прогоняет все слои, включая L4 (Шаг 5 в его протоколе):

```
Agent(memory-extractor): обработай новые сессии из L0 →
  • извлеки атомарные факты L1   → 10 — Claude/Memory/L1 Atomic Memory/{YYYY-MM-DD}.md
  • обнови сцены L2              → файл-день L2 Scene Blocks/{сцена}/{сцена} {YYYY-MM-DD}.md
                                   + ссылка в журнал тонкого ядра L2 {сцена}.md
  • актуализируй персону L3      → 10 — Claude/Memory/L3 Persona/persona.md (тонкое ядро;
                                   модули «Психологический профиль»/«Паттерны поведения» — точечно)
  • идиолект                     → файл-день L3 Persona/Идиолект/идиолект {YYYY-MM-DD}.md
                                   (включая рубрику «Как общается с людьми» по tg-экспортам Шага 0.5)
  • пополни Журнал архитектурных решений (см. раздел ниже)
                                 → 06 — Проекты/Журнал архитектурных решений/{YYYY-MM-DD} — {суть}.md
  • перестрой граф и лог L4      → файл-день L4 Semantic Graph/Log/Graph Log {YYYY-MM-DD}.md
                                   + ссылка в индекс Semantic Graph Log.md
```

> ⚡ **Бюджет токенов (2026-07-19):** память дроблена на тонкие ядра + файлы-дни. Большие накопительные файлы не читать целиком и не дописывать в них содержимое — только ядра (≤ ~15KB), файлы-дни за сегодня/вчера и целевой поиск. Полные правила — в определении memory-extractor.

> 🏷 **Пометка машинного авторства (2026-07-19):** каждая созданная ИИ заметка получает тег `ai-generated` в `tags:` frontmatter — файлы-дни L1/L2/идиолекта, лог L4, заметки ADR. Ставится в момент создания, не отдельным проходом. Тонкие ядра (`persona.md`, `L2 {сцена}.md`, `Идиолект и повадки.md`, MOC) не помечаются — это смешанные документы. Синонимов тега не заводить.
>
> Проверка охвата после прогона:
> ```bash
> grep -rL "ai-generated" "$VAULT/10 — Claude/Memory" --include='*.md' | grep -vE "L2 [a-z-]+\.md|persona\.md|Идиолект и повадки\.md|Semantic Graph Log\.md|README\.md"
> ```

Сцены L2: `obsidian-tools`, `personal-os-setup`, `psych-analysis`, `startup-ideas`, `dev-projects`, `life`.

> Если memory-extractor не запускается — выполни L4 вручную Шагами 3–4 ниже, журнал решений заполни сам по правилам ниже.

### Журнал архитектурных решений

`06 — Проекты/Журнал архитектурных решений/` — отдельное хранилище решений по программированию: архитектурные выборы, разборы багов и инцидентов, выводы из работы над проектами. Правила в `MOC — Журнал архитектурных решений.md` там же.

При обработке **dev-сессий** (сцена `dev-projects` и любые сессии с решениями по коду/инфраструктуре) извлекать состоявшиеся решения и оформлять каждое отдельной заметкой:

- Имя: `{YYYY-MM-DD} — {суть решения}.md`. Одна заметка — одно решение.
- Frontmatter: `type: adr`, `date`, `project` (wiki-link на проект, если есть), `status: принято`, `tags` — обязательно (`adr`, `dev`, тема: `микросервисы`/`база-данных`/`kafka`/`devops`/`инцидент`/…, проект: `isms`/…).
- Тело — **строго сплошным текстом**, как обычная заметка с мыслями: без списков, таблиц и заголовков-секций. Прозой: контекст и проблема → какие варианты рассматривались → что выбрано и почему → цена/компромиссы → при каких условиях пересмотреть. Связи `[[...]]` на проект и смежные решения.
- В журнал попадают только **состоявшиеся решения и разобранные инциденты**, не каждое обсуждение. Новую заметку дописать в список «Записи» в MOC.

## Порядок при «обнови всё»

Сначала `/update-memory` (наполняет память и индекс) — он уже выполняет Шаги 3–4 (граф + brainstorm) внутри. Отдельно `/brainstorm` после этого запускать не нужно.

## Связь с другими командами

- Только связи + граф без памяти → `/brainstorm`.
- Часть мастер-оркестратора `/personal-os` (раздел «Системные команды»).

## Бюджет контекста

Скилл — диспетчер: раздаёт задания агентам и принимает отчёты. Сам артефакты
агентов не читает и не «проверяет глазами» — проверка это ещё один агент.
Потолки: сессия 55% окна мягкий / 88% жёсткий, субагент 40k / 60k токенов.
Промежуточное — файлом в рабочее пространство команды, в диалог путь и суть.
Фича доведена до конца — чекпоинт и дальше с чистой сессии:

```bash
python3 .claude/hooks/checkpoint.py --note "<что сделано>" --next "<следующий шаг>"
```

Подробности — скилл `context-budget`.
