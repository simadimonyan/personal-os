# Аудит пробелов базы знаний — какие темы «не раскрыты хорошо»

Метод для агентов Tutor Lab: пройтись по разделу **«05 — Знания и навыки»** в Obsidian и
выдать карту тем, которые слабо проработаны, чтобы предложить ученику их закрыть.

> Раздел: `05 — Знания и навыки/` — подпапки `Computer Science/`, `Психология (теория)/`,
> `Аннотации книг/` и `MOC — 05 — Знания и навыки.md` (заявленная карта тем).
> База: ~550 заметок, граф связей построен (`vsearch stats` покажет актуальность).

## Шаг 1 — Собрать карту тем

```bash
DRV="node ~/.claude/skills/obsidian/driver.mjs"
# что вообще есть в разделе и подпапках
$DRV obsidian_list '{"path":"05 — Знания и навыки"}'
$DRV obsidian_list '{"path":"05 — Знания и навыки/Computer Science"}'
# заявленная карта тем — что автор сам считает важным
$DRV obsidian_read '{"name":"MOC — 05 — Знания и навыки"}'
# свежесть индекса для семантики/графа
python3 ~/Desktop/personal\ os/tools/obsidian/tools/obsidian_vsearch.py stats
```

## Шаг 2 — Сигналы «не раскрыто хорошо»

Тема/заметка попадает в карту пробелов, если срабатывает хотя бы один сигнал:

| Сигнал | Как обнаружить | Что значит |
|--------|----------------|-----------|
| **Заглушка / тонкая заметка** | `obsidian_read` → мало текста (заголовок + 1–3 строки, нет примеров) | тема названа, но не объяснена |
| **Сирота / слабая связность** | мало `[[ссылок]]` внутрь и наружу; низкая степень узла в графе (`build_graph` + `graph`) | знание изолировано, не встроено |
| **Висячая ссылка** | `[[X]]` упоминается в других заметках, но заметки `X` нет или она пустая | тема упомянута как нужная, но не раскрыта |
| **MOC без подложки** | пункт в `MOC — 05` есть, а заметок под ним нет/почти нет | декларация без содержания |
| **Перекос покрытия** | у подтемы 1 заметка против 15–20 у соседней | неравномерная глубина области |
| **Устарело (для навыков)** | `obsidian_recent` / даты — давно не трогалось, особенно быстро меняющиеся навыки/технологии | навык мог «протухнуть» |

Семантическая проверка широты темы:
```bash
VS="python3 ~/Desktop/personal\ os/tools/obsidian/tools/obsidian_vsearch.py"
# по ключевой подтеме мало релевантных чанков / низкий score → область тонкая
$VS hybrid "{подтема}" 10
# изолированные узлы без мостов к другим темам → не интегрировано в знание
$VS brainstorm "{тема}" 20 0.70
```

## Шаг 3 — Приоритизировать

Сортируй кандидатов по важности для ученика, а не по «дырявости» механически:
1. **Фундамент** (предпосылка для другого) тонкий → выше приоритет: ломает всё, что на нём стоит.
2. **Совпадает с целью/проектом** ученика (см. `00_learning_brief.md`, раздел `04 — Цели и задачи`, `06 — Проекты`) → выше.
3. **Заявлено в MOC, но пусто** → автор сам считал нужным — выше.
4. Изолированная экзотика без связи с целями → ниже.

## Шаг 4 — Отчёт «Карта пробелов»

Файл: `10 — Claude/Рабочее пространство/tutor/knowledge_gaps.md`. Формат:

```markdown
# Карта пробелов базы знаний — 05 Знания и навыки
**Дата:** {дата} · **Просмотрено заметок:** {N} · **Кандидатов:** {K}

## 🔴 Проработать в первую очередь
- **{Тема}** ([[заметка]] / нет заметки) — сигнал: {заглушка/сирота/висячая/перекос/устарело}.
  Почему важно: {фундамент для X / цель ученика / в MOC}. Что закрыть: {конкретно}.

## 🟡 Стоит укрепить
- ...

## ⚪ Можно позже
- ...

## Предложение
Готов запустить по любой теме: лекцию (lecturer) / мини-курс (curriculum-architect) /
задания (exercise-designer). Какую берём?
```

## Принцип

- Не выдавай «всё подряд тонкое» — это шум. Отбирай по важности для целей ученика.
- Различай **«нет заметки»** (тему не начинали) и **«заметка есть, но слабая»** (начали, не докрутили) — это разные действия.
- Всегда заканчивай **предложением проработать** — карта пробелов нужна, чтобы из неё вырос курс/лекция, а не чтобы пылиться.
