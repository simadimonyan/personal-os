# tg-freelance-blast — рассылка интро по фриланс-чатам Telegram

Шлёт одно сообщение (сопроводительное / самопрезентацию) по множеству Telegram-чатов
с безопасными паузами. Работает поверх скилла `telegram` (driver.cjs, реальный аккаунт
@dimitrisimonyan).

## ⚠️ Главное правило

Это **необратимое внешнее действие от реального аккаунта**. Никогда не рассылай без явного
подтверждения списка чатов и финального текста. Всегда: показать список → дождаться «го» →
только потом запускать.

## Когда применять

Триггеры: «разошли сопроводительное», «отправь интро во все фриланс-чаты», «предложи услуги
в чатах», «разошли по job-чатам», «откликнись в фриланс-чатах».

## Процесс

### 1. Текст сообщения
- Берёшь текст у пользователя. Если он просит — улучшаешь (читаемость, структура,
  буллеты, явный CTA в конце). Показываешь итог и что поменял.
- Сохраняешь финал в файл: `/tmp/freelance_msg.txt`.

### 2. Сбор и фильтрация чатов
```bash
node ~/.claude/skills/telegram/driver.cjs get_dialogs '{"limit":100}' 2>/dev/null
```
Отбирай **только супергруппы, где участники могут писать**: `isGroup: true`.
- ❌ `isGroup:false` (даже если `isChannel:true`) — это канал-вещалка, писать нельзя. Отбрось.
- ✅ Брать по теме: «фриланс», «freelance», «вакансии», «работа», «удалёнка», «помогатор»,
  «job», «jobs», профильные IT/dev-job чаты (под стек Димитри: Java/JVM/Android/backend).
- ❌ Отбрасывать не по теме: крипта, новости, языковые, региональные/тревел, SMM-специфику
  (если не просили), личные чаты/боты.

**Постоянный денилист (всегда исключать, не предлагать к рассылке):**
- `@jobs_it` (💻☕️ Jobs_IT, `-1001048585467`) — по правилам в закрепе разрешены **только вакансии от рекрутёров** («Only job vacancies message is allowed… Direct messages from HR»). Самопрезентация фрилансера/соискателя запрещена → мут/бан. Любая коммерция — только через @TheSorter. Сюда не слать.
- `@freelance_chat_birzha` — требует платную отправку (Telegram Stars), бесплатно не написать.

Формируешь список в файл `/tmp/freelance_chats.txt`, по строке на чат:
```
<chat_id>|<Название>
# строки с # — комментарий/пропуск
```

### 3. Подтверждение (обязательно)
Показываешь пользователю таблицу: № · название · @username, и **отдельно** — что
сознательно НЕ включил и почему. Предупреждаешь про риск: одинаковое промо с одного
аккаунта → часть чатов с анти-спамом может выдать варн/мут (в конкретном чате, не аккаунт).
Ждёшь явного «го» / «го N-M» / список номеров на удаление. Правишь файл чатов под ответ.

### 4. Рассылка с паузами
```bash
bash ~/.claude/skills/tg-freelance-blast/scripts/blast.sh \
  /tmp/freelance_msg.txt /tmp/freelance_chats.txt 40 60
```
Запускай в фоне (`run_in_background: true`) — прогон 15 чатов ≈ 10–12 мин.
Параметры 3-4 — диапазон паузы в секундах (по умолчанию 40–60).

### 5. Отчёт
Лог: `/tmp/tg_blast.log`. Скрипт пишет по каждому чату `OK (msgId=…)` или `FAIL :: error`,
в конце — `DONE: отправлено X/N, ошибок F`. По завершении дай пользователю сводку:
сколько ушло, какие FAIL и почему (часто: бан/мут/slow-mode/нет прав на отправку).

## Готчи

- Детект успеха — по `"success": true` (с пробелом! драйвер форматирует JSON с отступами).
  Скрипт это уже учитывает через `grep -E '"success":[[:space:]]*true'`. Не ломай.
- Текст с эмодзи/переносами безопасно упаковывается в JSON через `jq` — не собирай payload руками.
- `chat_id` групп — отрицательный (`-100…`). Можно и `@username`, но id надёжнее.
- Флуд-лимиты Telegram: не опускай паузу ниже ~30 сек и не гоняй по 30+ чатов подряд за раз.
- `406: ALLOW_PAYMENT_REQUIRED` — чат требует **платную отправку** (Telegram Stars).
  Не ошибка скрипта: туда бесплатно не написать. Помечай такой чат и пропускай (или предупреди,
  что нужна оплата). Известный пример — @freelance_chat_birzha.
- `CHAT_WRITE_FORBIDDEN` / `USER_BANNED_IN_CHANNEL` — нет прав писать / забанен в этом чате. Пропустить.
- `SLOWMODE_WAIT_X` — включён slow-mode; драйвер вернёт ошибку, чат пропускается (повторить позже вручную).
- При `AUTH_KEY_UNREGISTERED` — сессия протухла, переавторизация в `telegram-mcp-server/` (`node auth.js`).
