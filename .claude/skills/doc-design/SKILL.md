# Doc Design — дизайн презентаций и визуализации данных

Правила оформления для визуальных артефактов. Детальные приёмы кода (python-pptx, matplotlib) — в `references/tooling.md` (читай при генерации файлов).

## Часть 1. Презентации

### Главный принцип: одно сообщение на слайд
Заголовок слайда = **вывод**, не тема. «Выручка выросла на 40% за квартал» вместо «Выручка». Зритель должен понять суть за 3 секунды.

### Сетка и выравнивание
- Всё располагай по невидимой сетке (например, 12 колонок). Единые поля (margin) на всех слайдах.
- Элементы выравниваются по краям/центрам друг друга. Хаотичные отступы = небрежность.
- Поля слайда: не вплотную к краю, оставляй «безопасную зону» ~5–7% от края.

### Типографика
- **Максимум 2 шрифта** (заголовочный + текстовый). Контрастная, но сочетающаяся пара.
- Иерархия размеров: заголовок слайда ≥ 32 pt, подзаголовок ~24 pt, тело ≥ 18–24 pt. На слайдах мельче 18 pt не опускаться.
- Выравнивание текста — по левому краю (читается лучше, чем по центру для длинного текста).

### Цвет
- Палитра: 1 основной, 1 акцентный, 2–3 нейтральных. Не больше.
- Акцентный цвет — только для главного на слайде (направляет взгляд). Если всё выделено — ничего не выделено.
- Контраст текст/фон: тёмный на светлом или наоборот, проверяй читаемость с расстояния.
- Фирменный стиль из ТЗ (бренд-цвета, логотип) — приоритет над дефолтом.

### Содержание слайда
- Ориентир **6×6**: ~6 пунктов, ~6 слов в пункте. Слайд — опора для речи, не текст доклада.
- Числа → график (от `data-visualizer`), не таблица текста.
- Воздух (пустое пространство) — это структура, а не «недозаполнено». Не уплотняй до края.
- Один визуальный акцент на слайд (крупное число, образ, график).

### Структура колоды (адаптируй под тип)
Титул → контекст/проблема → ключевая мысль → аргументы (1 тезис = 1 слайд) → решение/результат → выводы → контакты/CTA.
Типы: защита (упор на результаты и новизну), отчёт (структура и данные), продажа (проблема→решение→выгода), обучение (от простого к сложному, повтор ключевого).

### Единство
Цвета, шрифты, отступы, стиль иконок и графиков — одинаковы во всей колоде. Используй мастер-слайд / шаблон.

## Часть 2. Визуализация данных

### Выбор типа графика (под данные)
| Данные | График |
|--------|--------|
| Динамика во времени | линейный |
| Сравнение категорий | столбчатый (горизонт. при длинных подписях) |
| Доли целого (2–4) | круговой / пончик |
| Доли целого (>4) | столбчатый, не круговой |
| Зависимость двух величин | точечный (scatter) |
| Распределение | гистограмма / box plot |
| Состав во времени | стек-область |
| Матрица/плотность | тепловая карта |
Не уверен → бери самый простой читаемый (бар или линия).

### Честность (критично)
- **Ось Y от нуля** для столбчатых. Обрезанная ось искажает масштаб — отклонение только осознанно и с пометкой.
- Не путай корреляцию и причинность в подписях.
- Не используй объём/3D/площадь для передачи одного числа — искажает восприятие.

### Чистота (data-ink)
- Убери лишнее: тяжёлые сетки, рамки, тени, дубли легенд, фоновые заливки.
- Подписи обязательны: заголовок, оси с единицами, источник, дата.
- Прямые подписи у линий/баров лучше отдельной легенды, когда возможно.

### Цвет в графиках
- Категориальные данные → различимая качественная палитра.
- Последовательные (величина) → один градиент.
- Дивергентные (отклонение от нуля) → две стороны от нейтрального центра.
- Акцент → один контрастный цвет на главную серию, остальное приглушить.
- Доступность: не полагайся только на красный/зелёный (дальтонизм); добавляй форму/паттерн/подпись.

## Принцип применения
1. Определи артефакт: презентация → Часть 1; график → Часть 2; вёрстка документа → Часть 1 (сетка, типографика) + ГОСТ из `gost-standards`.
2. Есть образец/фирменный стиль в ТЗ → следуй ему, эти правила — для пробелов.
3. Код генерации (.pptx, графики) — см. `references/tooling.md`.
4. Всегда сначала раскадровка/эскиз для согласования, потом финальная генерация.
