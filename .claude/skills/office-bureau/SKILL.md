# Office Bureau — Agent Team офисной работы

Координирую команду по созданию и оформлению документов: от выявления требований до готовых .docx/.pdf/.pptx по ГОСТ и правилам делопроизводства.

**Agent Team:**
- `office-scout` — выявление требований к документу (точка входа, всегда спрашивает: тип, образец, нужна ли презентация/графики)
- `document-writer` — отчёты, договоры, письма, приказы, записки, справки по ГОСТ Р 7.0.97 и делопроизводству
- `data-visualizer` — графики и диаграммы (matplotlib/plotly), честная визуализация
- `presentation-designer` — оформление и дизайн презентаций (.pptx), вёрстка

**Вспомогательные (Personal OS):**
- `knowledge-agent` — Obsidian: сохранение шаблонов и готовых документов

**Скиллы команды:** `gost-standards` (document-writer), `doc-design` (presentation-designer, data-visualizer).

**Режим выполнения:** Agent Team Hybrid (scout → pipeline/fan-out по типу документа)

**Кросс-командное взаимодействие:**
- Принимает: научный текст от Research Lab (`academic-writer`) для оформления в .docx/PDF по ГОСТ или презентацию.
- Передаёт: готовые документы → Obsidian.
- Протокол: `.claude/skills/agent-context/references/cross-team.md`

## Phase 1: Выявление требований (office-scout)

**Режим:** одиночный агент, интерактивный. **Этот шаг обязателен всегда** — не начинаем документ вслепую.

```

Запрос пользователя: {запрос}. Выясни через AskUserQuestion: тип документа, стандарт,

```

Дождись ТЗ. Особенно важны ответы: нужна ли презентация и есть ли образец оформления.

## Phase 2: Производство (pipeline / fan-out по типу)

**Режим:** агент-команда. Состав и порядок зависят от ТЗ.

| Что в ТЗ | Кто работает | Порядок |
|----------|-------------|---------|
| Только текстовый документ | `document-writer` | одиночно |
| Документ + графики | `data-visualizer` → `document-writer` | visualizer строит графики, writer вставляет |
| Презентация | `data-visualizer` (если нужны графики) → `presentation-designer` | designer собирает .pptx |
| Документ + презентация | `document-writer` + `data-visualizer` → `presentation-designer` | контент и графики → в колоду |

- `document-writer` читает `gost-standards`, строит документ, выдаёт .docx/.pdf.
- `data-visualizer` читает `doc-design`, строит графики в `10 — Claude/Рабочее пространство/office/charts/`.
- `presentation-designer` читает `doc-design`, делает раскадровку (`storyboard_*.md`) → согласование → `.pptx`.

Если в ТЗ дан **образец** — все агенты воспроизводят его структуру/стиль приоритетно.

## Обработка ошибок

- python-pptx / python-docx / matplotlib недоступны → pip install; при невозможности — раскадровка/Markdown/таблица + спецификация, пометка о ручной сборке.
- Образец недоступен → применяем общий ГОСТ/дефолт-дизайн, помечаем допущение.
- Конфликт «образец vs обязательный реквизит ГОСТ» → следуем обязательному, сообщаем пользователю.
- Кириллица в PDF/графиках → шрифт с поддержкой (Times New Roman / DejaVu Sans).
- Агент не завершил → 1 повтор, затем выдача без его части с пометкой.

## Тестовые сценарии

**Полный цикл:** «Сделай отчёт по проекту с графиками и презентацией» → office-scout (ТЗ: образец? презентация? да) → data-visualizer (графики) + document-writer (отчёт .docx по ГОСТ) → presentation-designer (.pptx) → Obsidian.

**Частичный:** «Поменяй палитру графиков на фирменную» → читается ТЗ и скрипты charts, запускается только data-visualizer.

**Ошибка:** python-pptx не ставится → presentation-designer отдаёт детальную раскадровку + reveal.js HTML, помечает «требуется ручная сборка .pptx».

## Бюджет контекста

Скилл — диспетчер: раздаёт задания агентам и принимает отчёты. Сам артефакты
агентов не читает и не «проверяет глазами» — проверка это ещё один агент.
Потолки: сессия 55% окна мягкий / 88% жёсткий, субагент 40k / 60k токенов.
Промежуточное — файлом в рабочее пространство команды, в диалог путь и суть.
Фича доведена до конца — чекпоинт и дальше с чистой сессии:

```bash
python3 .claude/hooks/checkpoint.py --note "<что сделано>" --next "<следующий шаг>"
```
