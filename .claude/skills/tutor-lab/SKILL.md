# Tutor Lab — Agent Team тьюторов

Координирую команду преподавателей: по заданной теме команда строит персональную программу обучения, пишет лекции, создаёт задания и тесты, собирает всё в рабочий план и сопровождает обучение.

**Agent Team:**
- `learning-needs-analyst` — выявление требований к обучению (точка входа: уровень, цель, сроки, стиль)
- `curriculum-architect` — программа обучения: модули, последовательность, цели, контрольные точки
- `lecturer` — лекции, объяснения, конспекты по модулям
- `exercise-designer` — задания, упражнения, практические проекты
- `assessment-designer` — квизы, контрольные, экзамены, рубрики
- `learning-coach` — сборка курса в план + сопровождение, прогресс, повторение

**Вспомогательные (Personal OS):**
- `knowledge-agent` — Obsidian: материалы по теме, сохранение курса и прогресса

**Скиллы команды:** `pedagogy` (все проектирующие агенты), `obsidian`, `zotero`.

**Режим выполнения:** Agent Team Hybrid (scout → архитектор → fan-out материалы → сборка)

**Кросс-командное взаимодействие:**
- Запрашивает: Research Lab (`deep-researcher`) — глубина и первоисточники по теме для лекций.
- Передаёт: Office Bureau — оформление курса (PDF-программа, презентации-лекции).
- Протокол: `.claude/skills/agent-context/references/cross-team.md`

## Phase 1: Выявление требований (learning-needs-analyst)

**Режим:** одиночный агент, интерактивный.

```
Agent(learning-needs-analyst, model="opus"): прочитай определение .claude/agents/learning-needs-analyst.md.
Запрос пользователя: {тема + запрос}. Выясни через AskUserQuestion уровень, цель, целевой результат,
сроки/темп, стиль, формат. Сохрани ТЗ в 10 — Claude/Рабочее пространство/tutor/00_learning_brief.md.
```

Дождись ТЗ — без него курс не строится. Если запрос ясен (уровень и цель указаны), аналитик формирует ТЗ без лишних вопросов.

## Phase 2: Программа (curriculum-architect)

**Режим:** одиночный агент (остальные зависят от его выхода).

```
Agent(curriculum-architect, model="opus"): прочитай определение и скилл pedagogy.
Вход: 00_learning_brief.md. Построй карту курса → 10 — Claude/Рабочее пространство/tutor/01_curriculum.md
(цели, модули, последовательность, прогрессия, контрольные точки, график).
```

Карта курса — каркас для всей команды. Если объём не влезает в срок — архитектор предлагает приоритизацию, оркестратор согласует с пользователем.

---

## Phase 3: Материалы (fan-out по модулям)

**Режим:** агент-команда, параллельно (`run_in_background: true`). Все читают `01_curriculum.md` и скилл `pedagogy`.

| Агент | Задача | Выход |
|-------|--------|-------|
| `lecturer` | лекции и конспекты по модулям | `lectures/M{N}_*.md` |
| `exercise-designer` | задания по модулям (на пройденное) | `exercises/M{N}_*.md` |
| `assessment-designer` | квизы/контрольные по целям | `assessments/M{N}_*.md` |

Зависимость: задания и тесты опираются на лекции (на пройденный материал) — поэтому lecturer идёт чуть впереди по каждому модулю, либо работаем помодульно (лекция M1 → задания+тест M1, параллельно лекция M2). Координация через SendMessage. Если ТЗ просит только лекции или только задания — запускай нужных.

За глубиной/первоисточниками lecturer обращается в Research Lab (`deep-researcher`).

## Phase 4: Сборка и сопровождение (learning-coach)

**Режим:** одиночный агент.

```
Agent(learning-coach, model="opus"): прочитай определение и скилл pedagogy.
Вход: 00_brief, 01_curriculum, lectures/, exercises/, assessments/.
Собери единый учебный план → 10 — Claude/Рабочее пространство/tutor/PLAN.md (маршрут по шагам, график,
интервальное повторение, milestone'ы, чек-лист прогресса). Дальше — сопровождение по запросу.
```

`PLAN.md` — главный артефакт для ученика. Дальше learning-coach остаётся точкой сопровождения: отвечает на вопросы, ведёт прогресс, корректирует план по результатам проверок.

Нужно **оформление** (PDF-курс, презентации-лекции) → передать Office Bureau.

## Данные между агентами

- **Файлы**: `10 — Claude/Рабочее пространство/tutor/` — единый канал (brief → curriculum → материалы → PLAN). Нумерация модулей `M{N}` связывает лекции, задания и тесты.
- **Сообщения**: exercise/assessment-designer запрашивают у lecturer статус по модулю; coach шлёт команде запросы на доработку.
- **Финал**: курс и PLAN.md в пользовательский путь / Obsidian; `10 — Claude/Рабочее пространство/` сохраняется.

## Обработка ошибок

- Уровень ученика неясен → learning-needs-analyst даёт диагностику, не угадываем.
- Объём не влезает в срок → curriculum-architect приоритизирует «ядро + опционально», сообщаем пользователю.
- lecturer не уверен в фактах → запрос в Research Lab, без выдумывания.
- Агент не завершил → 1 повтор, затем сборка без его части с пометкой о пробеле в PLAN.
- Тема чисто практическая/теоретическая → exercise-designer адаптирует тип заданий (кейсы/мысленные эксперименты).

## Тестовые сценарии

**Полный цикл:** «Научи меня основам статистики за месяц с нуля» → analyst (ТЗ: уровень нулевой, цель, темп) → architect (программа на 4 модуля) → lecturer + exercise-designer + assessment-designer (материалы) → coach (PLAN.md с повторениями) → Obsidian.

**Частичный:** «Усложни задания по модулю 2 и добавь итоговый тест» → читаются curriculum и lectures M2, запускаются только exercise-designer + assessment-designer.

**Ошибка:** lecturer не уверен в теме → запрос в Research Lab (deep-researcher), лекция дополняется проверенными фактами с источниками; остальная команда работает штатно.

## Бюджет контекста

Скилл — диспетчер: раздаёт задания агентам и принимает отчёты. Сам артефакты
агентов не читает и не «проверяет глазами» — проверка это ещё один агент.
Потолки: сессия 55% окна мягкий / 88% жёсткий, субагент 40k / 60k токенов.
Промежуточное — файлом в рабочее пространство команды, в диалог путь и суть.
Фича доведена до конца — чекпоинт и дальше с чистой сессии:

```bash
python3 .claude/hooks/checkpoint.py --note "<что сделано>" --next "<следующий шаг>"
```

Подробности — скилл `context-budget`.
