# Startup Lab — Agent Team стартапа

Координирую команду специалистов для разработки продуктов: от идеи до контента и команды.

**Agent Team:**
- `market-researcher` — исследование рынка, гипотезы, NotebookLM, Telegram-разведка
- `product-manager` — PRD, roadmap, user stories, hypothesis canvas
- `growth-marketer` — позиционирование, ICP, конкурентный анализ, GTM
- `smm-specialist` — контент-стратегия, контент-план, готовые посты в стиле Димитри
- `business-psychologist` — перфоманс предпринимателя, деловое общение, бизнес-трекинг
- `hr-specialist` — найм, вакансии, onboarding, культура, резюме, сопроводительные письма

**Вспомогательные (Personal OS):**
- `knowledge-agent` — Obsidian: профиль Димитри, накопленные знания, сохранение артефактов
- `action-agent` — Telegram-каналы, hh.ru, отправка постов

**Режим выполнения:** Agent Team Hybrid

**Кросс-командное взаимодействие:**
- Принимает: PRD-запросы от dev-lab, психологический профиль от psych-team
- Передаёт: PRD + позиционирование → dev-lab; инсайты об аудитории → psych-team
- Протокол: `.claude/skills/agent-context/references/cross-team.md`

## Phase 0: Проверка контекста

### 0a. Контекст рабочей папки
При запуске определить режим:
- `10 — Claude/Рабочее пространство/startup/` существует + запрос на доработку → **частичный перезапуск** нужного агента
- `10 — Claude/Рабочее пространство/startup/` существует + новая идея → переименовать в `10 — Claude/Рабочее пространство/startup_prev/`, начать заново
- `10 — Claude/Рабочее пространство/startup/` нет → **первый запуск**, создать структуру директорий

### 0b. Загрузка контекста агентов из Obsidian

Спроси пользователя: **«Загрузить контекст предыдущей сессии стартап-команды? (да/нет)»**

Если **да** — читай контекст агентов, которые будут задействованы в этой сессии:
```bash

node ~/.claude/skills/obsidian/driver.mjs obsidian_read '{"name":"growth-marketer"}'
node ~/.claude/skills/obsidian/driver.mjs obsidian_read '{"name":"smm-specialist"}'
node ~/.claude/skills/obsidian/driver.mjs obsidian_read '{"name":"business-psychologist"}'
node ~/.claude/skills/obsidian/driver.mjs obsidian_read '{"name":"hr-specialist"}'
```

Найденный контекст включай в prompt каждого агента при его запуске (секция "Контекст предыдущей сессии").

Особая ценность:
- **market-researcher**: прошлые исследования экономят повторный поиск
- **smm-specialist**: готовый `style_profile.md` из прошлой сессии — не надо пересобирать стиль
- **business-psychologist**: динамика блоков во времени — ценнее разовых наблюдений
- **hr-specialist**: история открытых вакансий и культурных решений — не повторяй уже принятые

Если файлы не найдены — агенты начинают без контекста (первая сессия).

Полный протокол: `.claude/skills/agent-context/SKILL.md`

## Workflow-шаблоны

### 🚀 Полный продуктовый цикл (Agent Team)
**Режим:** Agent Team Pipeline + Fan-out

```
1. Зафиксировать brief в 10 — Claude/Рабочее пространство/startup/brief.md

2. Загрузить из Obsidian:
   - Профиль Димитри (раздел 01, 04)
   - Предыдущие исследования по теме (поиск)
   - Контексты агентов (раздел 10)

3. [TaskCreate] Задачи с зависимостями:
   T1: market-researcher — research (независима)
   T2: product-manager — PRD (зависит от T1)
   T3: growth-marketer — positioning+ICP+GTM (зависит от T1, T2)
   T4: smm-specialist — контент (зависит от T2, T3)

4. [ЗАПУСК Agent Team]
   Агенты работают по TaskList, синхронизируются через 10 — Claude/Рабочее пространство/ файлы
   Каждый агент:
   - Читает Obsidian (профиль + накопленные знания по теме)
   - Читает входные файлы предыдущих агентов
   - Пишет свои артефакты
   - Синхронизирует контекст в Obsidian по завершении

5. knowledge-agent: сохранить в Obsidian раздел 06 Проекты

6. Вывести пользователю сводку артефактов
```

### 🔬 Проверка гипотезы
**Режим:** Sub-agent

```
1. Зафиксировать гипотезу в brief.md

2. [market-researcher]:
   - Загрузить источники в NotebookLM (статьи, исследования, отчёты по теме)
   - Задать вопросы NotebookLM для проверки гипотезы
   - Изучить Telegram-каналы для живых примеров
   - Создать hypothesis_report в research/
   
3. [product-manager]: на основе результатов уточнить или пересмотреть гипотезу

4. Вывести вывод: гипотеза подтверждена / опровергнута / нужно больше данных
```

### ✍️ Контент-спринт (только посты)
**Режим:** Sub-agent

```
1. [smm-specialist]:
   a. Изучить стиль письма Димитри:
      - knowledge-agent: прочитать последние 20-30 личных заметок из Obsidian (раздел 01, 02)
      - action-agent: get_dialogs → get_chat_history для 3-5 личных чатов
      - Составить профиль стиля: лексика, длина предложений, структуры, темы
   b. Прочитать позиционирование из 10 — Claude/Рабочее пространство/startup/marketing/ (если есть)
   c. Написать 5-10 постов полностью в стиле Димитри
   d. Показать пользователю черновики на ревью

2. При одобрении → action-agent отправляет в Telegram с подтверждения
```

### 🧠 Бизнес-трекинг / перфоманс предпринимателя
**Режим:** Sub-agent

```
1. [business-psychologist]:
   a. Прочитать бизнес-контекст из 10 — Claude/Рабочее пространство/startup/ (если есть)
   b. Если есть psych-analysis → прочитать 10 — Claude/Рабочее пространство/psych/final_report.md
   c. knowledge-agent: прочитать бизнес-заметки из Obsidian (разделы 04, 06)
   d. action-agent: деловые переписки из Telegram (только чтение)
   e. Создать бизнес-чекап в 10 — Claude/Рабочее пространство/startup/performance/

2. knowledge-agent: сохранить чекап в Obsidian если нужно

3. Вывести пользователю: паттерны, блоки, фокус на следующий период
```

### 👥 HR стартапа: найм и команда
**Режим:** Sub-agent

```
1. [hr-specialist]:
   a. Прочитать brief + product roadmap из 10 — Claude/Рабочее пространство/startup/
   b. Если есть psych данные → прочитать 10 — Claude/Рабочее пространство/psych/final_report.md (командный контекст)
   c. Исследовать через NotebookLM: практики найма, зарплатные бенчмарки (10–50 источников)
   d. Создать запрошенные HR-артефакты:
      - hiring_strategy.md (стратегия + приоритеты)
      - jd_{роль}.md (описание вакансии)
      - hiring_process_{роль}.md (процесс + scorecard)
      - onboarding_{роль}.md (план адаптации)
      - culture.md (ценности и культура)

2. knowledge-agent: сохранить в Obsidian (раздел 06 Проекты или 04 Цели)

3. Вывести пользователю: артефакты + рекомендации по приоритетам
```

### 📄 Личный HR: резюме, профиль, сопроводительные письма
**Режим:** Sub-agent

```
1. [hr-specialist]:
   a. knowledge-agent: прочитать актуальное резюме из Obsidian (поиск по "резюме" / "CV")
   b. action-agent (если нужно): прочитать профиль hh.ru через hh_get_resumes
   c. Выполнить запрошенную задачу:
      - Обновить/улучшить резюме
      - Написать сопроводительное письмо под конкретную вакансию
      - Подготовить к интервью (вопросы + ответы)
      - Обновить профиль в Obsidian
   d. Сохранить результат в 10 — Claude/Рабочее пространство/startup/hr/personal/

2. knowledge-agent: обновить профиль в Obsidian если изменились данные

3. При сопроводительном письме для hh.ru → action-agent отправляет только с подтверждения
```

### 🗺️ Быстрый рыночный обзор
**Режим:** Sub-agent

```
1. [market-researcher]:
   - Telegram-каналы конкурентов через action-agent
   - NotebookLM для глубины
   - Вывод: market_overview + competitors

2. [growth-marketer]: на основе обзора — positioning + ICP
```

## Инструкция SMM-специалисту по стилю письма

Перед созданием контента SMM-специалист **обязан** изучить стиль Димитри:

**Шаг 1 — Obsidian:**
Задача для knowledge-agent: прочитать 20-30 последних личных заметок из разделов 01 и 02 Органона.

**Шаг 2 — Telegram:**
Задача для action-agent: прочитать историю сообщений Димитри в 3-5 личных чатах (только его сообщения, не собеседников).

**Шаг 3 — Профиль стиля:**
SMM-специалист сохраняет `10 — Claude/Рабочее пространство/startup/content/style_profile.md`:
- Средняя длина предложения
- Любимые слова и выражения
- Структуры (списки / сплошной текст / вопросы)
- Эмоциональный тон (ирония, прямолинейность, юмор?)
- Темы которые Димитри поднимает органично
- Что НЕ характерно для его стиля

## NotebookLM в стартап-команде

**Все агенты команды умеют исследовать через NotebookLM.** Используй это при построении задач агентам.

Стандарт для market-researcher: загрузить 10–50 источников, задать вопросы по полному охвату предметной области, итог — явное резюме ✅/⚠️/❓.

Другие агенты (product-manager, growth-marketer, smm-specialist, business-psychologist) также могут использовать NotebookLM для обогащения своего анализа — каждый согласно своему протоколу (см. соответствующий `.claude/agents/{name}.md`).

При постановке задачи агенту явно укажи: «Если нужно — используй NotebookLM для research, загрузи 10–50 источников по теме».

## Опросы на Яндекс Формах

Команда умеет собирать не только кабинетные данные, но и живые ответы: опрос
описывается JSON-спекой и выкладывается в Яндекс Формы одной командой.

```bash
cd tools/yandex-forms
node yaapi.mjs check <спека.json>              # проверить, ничего не создавая
node yaapi.mjs build <спека.json> --publish    # собрать и опубликовать
```

Спеки агенты кладут в `10 — Claude/Рабочее пространство/startup/research/surveys/{имя}.json`.

Кто чем пользуется: `market-researcher` (валидация гипотез, скрининг перед кастдевом),
`product-manager` (обратная связь, приоритизация фич), `growth-marketer` (ICP, проверка
формулировок), `smm-specialist` (опрос подписчиков), `hr-specialist` (скрининг, культура).

**Перед сборкой формы всегда показывай пользователю список вопросов и жди «да»** — форма
уходит живым людям от его имени. Публиковать без подтверждения нельзя.

📖 Формат спеки, типы вопросов и правила хорошего опроса: `references/surveys.md`

## Запуск агентов

Используй `Agent` tool:
- `subagent_type: "general-purpose"` для всех
- `model: "opus"` обязательно
- Для параллельного выполнения: `run_in_background: true`

В prompt включай:
1. Путь к файлу агента: `.claude/agents/{name}.md` — попроси прочитать
2. Конкретные пути к входным/выходным файлам
3. Ожидаемый формат результата

## Обработка ошибок

- NotebookLM недоступен → market-researcher работает только с Telegram и Obsidian, отмечает ограничение
- Telegram недоступен → без разведки из каналов, пометить артефакты как "без live-данных"
- Нет данных для стиля → smm-specialist пишет в нейтральном профессиональном тоне, предупреждает пользователя
- Агент не завершил → 1 повтор, затем продолжить без этого блока, отметить в итоге

## Тестовые сценарии

**Нормальный:** "придумай продукт для студентов которые хотят зарабатывать" → brief → research → PRD → positioning → 10 постов в стиле Димитри → сохранить в Obsidian

**Ошибочный:** Telegram и NotebookLM недоступны → research только из Obsidian → PRD с явными assumption-метками → посты в нейтральном тоне + предупреждение

## Бюджет контекста

Скилл — диспетчер: раздаёт задания агентам и принимает отчёты. Сам артефакты
агентов не читает и не «проверяет глазами» — проверка это ещё один агент.
Потолки: сессия 55% окна мягкий / 88% жёсткий, субагент 40k / 60k токенов.
Промежуточное — файлом в рабочее пространство команды, в диалог путь и суть.
Фича доведена до конца — чекпоинт и дальше с чистой сессии:

```bash
python3 .claude/hooks/checkpoint.py --note "<что сделано>" --next "<следующий шаг>"
```

Подробности — скилл `context-budget`.
