# ГОСТ-стандарты оформления документов

Справочник правил оформления. Агент применяет их буквально. Детальные примеры библиографических описаний — в `references/bibliography-examples.md` (читай при оформлении списка литературы). Образцы структуры документов — в `references/document-templates.md`.

## Общие параметры страницы (по умолчанию)

| Параметр | Значение |
|----------|----------|
| Шрифт | Times New Roman |
| Кегль | 14 (таблицы/сноски — 12) |
| Межстрочный интервал | 1,5 (научные работы), 1–1,5 (ОРД) |
| Поля | левое 30 мм (под подшивку) / 20 мм, правое 10 мм, верхнее 20 мм, нижнее 20 мм |
| Абзацный отступ | 1,25 см |
| Выравнивание текста | по ширине |
| Нумерация страниц | сквозная, арабскими, внизу по центру или вверху справа; титул считается, но номер не ставится |
| Цвет текста | чёрный |

## 1. Научные работы — ГОСТ 7.32-2017 (отчёт о НИР, рефераты, статьи)

**Структура (порядок):**
1. Титульный лист
2. Реферат/аннотация (для статьи — аннотация 150–250 слов + 5–7 ключевых слов)
3. Содержание (оглавление)
4. Введение — актуальность, проблема, цель, задачи, объект, предмет, степень изученности
5. Основная часть — главы/разделы (теория → анализ → результаты)
6. Заключение — выводы по задачам, новизна, перспективы
7. Список использованных источников
8. Приложения

**Заголовки:** разделы нумеруются арабскими (1, 1.1, 1.1.1). Заголовки разделов — с новой страницы, прописными или с заглавной, без точки в конце, не подчёркиваются. Подразделы — с абзаца.

**Нумерация:** разделы, рисунки, таблицы, формулы — сквозная или по разделам. Рисунок: подпись снизу по центру «Рисунок 1 — Название». Таблица: «Таблица 1 — Название» сверху слева. Формулы — справа в круглых скобках (1).

## 2. Организационно-распорядительная документация — ГОСТ Р 7.0.97-2016

Применяется к отчётам делового типа, письмам, приказам, запискам, справкам, договорам.

**Реквизиты документа (основные):**
- Наименование организации (автора)
- Справочные данные об организации (для писем: адрес, тел., email, ОГРН, ИНН)
- Наименование вида документа (ПРИКАЗ, АКТ, СПРАВКА) — кроме письма
- Дата документа (08.10.2026 или 8 октября 2026 г.)
- Регистрационный номер
- Место составления (для писем не указывается)
- Адресат (кому)
- Заголовок к тексту (о чём документ, отвечает на «о чём?»)
- Текст документа
- Подпись (должность — подпись — расшифровка)
- Печать (при необходимости)
- Отметка об исполнителе (ФИО, телефон — мелким шрифтом внизу)
- Гриф утверждения / согласования (при необходимости)

**Текст:** делового стиля, от 3-го лица или безличный. В приказе — «ПРИКАЗЫВАЮ». Допускается деление на разделы, пункты, подпункты (нумерация арабскими).

## 3. Текстовые документы — ГОСТ 2.105 (ЕСКД, общие требования)

Базовые требования к построению текстовых документов: рубрикация, перечисления, оформление таблиц, иллюстраций, приложений. Перечисления: дефис или строчная буква со скобкой `а)`, при детализации — арабские со скобкой `1)`. Применяй для технических и пояснительных текстов.

## 4. Библиография

**Затекстовые ссылки (ГОСТ Р 7.0.5-2008):** в тексте в квадратных скобках — `[5]` или `[5, с. 23]`. Список «Список использованных источников» в конце.

**Библиографическое описание (ГОСТ 7.0.100-2018 / ранее 7.1-2003):** единообразно для всего списка. Порядок: по алфавиту, или по порядку упоминания, или по группам (нормативные акты → книги → статьи → электронные ресурсы).

Полные шаблоны и примеры описаний (книга, статья, электронный ресурс, диссертация, ГОСТ, закон) — в `references/bibliography-examples.md`. **Читай этот файл перед составлением списка литературы.**

## Принцип применения

1. Определи тип документа → выбери стандарт (научный → 7.32; деловой → 7.0.97).
2. Если в ТЗ есть **образец** — его конкретные параметры приоритетнее общих дефолтов (если не нарушают обязательные реквизиты).
3. Применяй параметры страницы, структуру, реквизиты, нумерацию буквально.
4. Список литературы — всегда сверяй с `references/bibliography-examples.md`.
5. Спорные/неуказанные параметры — применяй дефолт из таблицы выше, помечай как допущение.

> Стандарты периодически обновляются. Если у пользователя есть актуальная методичка/требования издания — они приоритетнее общих правил.
