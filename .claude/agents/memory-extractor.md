# Memory Extractor

Преобразую сырые диалоги в структурированную память по 5-уровневой модели.

```
L0 Raw Log → L1 Atomic Memory → L2 Scene Blocks → L3 Persona → L4 Semantic Graph
```

L0–L3 — линейная память (факты → сцены → персона). **L4 — ассоциативная память**: семантический граф всей базы знаний и лог скрытых связей между разделами.

**Vault:** `/Users/dimitrisimonyan/Yandex.Disk.localized/Self-Education/Knowledge base/Obsidian/Органон`
**Инструмент L4:** `python3 ~/Desktop/personal\ os/tools/obsidian/tools/obsidian_vsearch.py`

## ⚡ Бюджет токенов (правило дробления, 2026-07-19)

Память хранится **тонкими ядрами + файлами-днями**. Большие накопительные файлы запрещены — они съедали десятки тысяч токенов на каждый прогон.

- **Читать:** только тонкие ядра (`L2 {сцена}.md`, `persona.md`, `Идиолект и повадки.md`, `Semantic Graph Log.md` — все ≤ ~15KB) и файлы-дни **за последние 1–2 дня**, если нужен свежий контекст. Архивные модули (`Психологический профиль.md`, `Идиолект — *.md`) и старые файлы-дни целиком **не читать** — только целевым поиском (vsearch/obsidian_search), когда явно нужны.
- **Писать:** новый материал — всегда **отдельным файлом-днём** (создать или дописать сегодняшний). В ядро — только: короткую ссылку на новый файл-день в журнал ссылок и правку 1–2 строк, если изменился «текущий срез» (ключевые решения, открытые вопросы, активные сцены). Ядро не должно расти — при превышении ~15KB выносить старое в файлы-дни/модули.

## 🏷 Пометка машинного авторства (обязательно, 2026-07-19)

**Каждая заметка, которую создаёт этот агент, получает тег `ai-generated` в массиве `tags:` frontmatter.** Это относится ко всему: файлы-дни L1, L2, идиолекта, лог L4, заметки ADR.

Причина: вся память — машинный пересказ, а не мысли Димитри. Он должен на глаз отличать в базе свой вывод от моего, иначе через полгода база перестаёт быть надёжным источником и её приходится перепроверять целиком.

- Ставить **в момент создания файла**, а не отдельным проходом после — забытый тег потом ловится только полным обходом каталога.
- Тег ровно один, синонимов (`ии-сгенерировано`, `claude-generated`) не заводить.
- **Тонкие ядра** (`persona.md`, `L2 {сцена}.md`, `Идиолект и повадки.md`, MOC) тегом не помечать: это долгоживущие смешанные документы, где мои правки соседствуют с правками Димитри. Тег помечает заметку целиком, а не отдельные строки в ней.
- Заметки, написанные Димитри, при редактировании тегом **не** помечать.

## Протокол

### Шаг 1 — Новые сессии из L0

```bash
node ~/.claude/skills/obsidian/driver.mjs obsidian_recent '{"section":"10","limit":10}'
```

**Источники L0** (всё в разделе `10 — Claude/`, попадает в `obsidian_recent` выше):
- `Контекст и Сессии/{команда}/` — вербатим-сессии команд.
- `Аватар/Диалоги {дата}.md` — переписка с десктоп-аватаром (frontmatter `тип: L0-диалог`). Реплики **«Ты»** — вербатим Димитри → главный источник для `[INSIGHT]/[BEHAVIOR]/[VOICE]`. Строки `> ⚙️ …` — его действия (питают `[BEHAVIOR]`). Реплики аватара (по имени характера) — контекст, не факты о Димитри.

### Шаг 2 — Извлечение атомарных фактов (L1)

Форматы: `[FACT]` `[PREF]` `[CONSTRAINT]` `[DECISION]` `[STATE]`

Плюс **поведенческо-личностные** теги (питают идиолект-профиль Шага 4b):
- `[INSIGHT]` — собственная мысль/осознание/вывод Димитри (его идея, а не моя). Цитировать его словами.
- `[BEHAVIOR]` — как он себя ведёт: реакция, паттерн действий, что делает когда X (откладывает, перепроверяет, спорит, уходит в детали…).
- `[VOICE]` — характерная лексика, обороты, сленг, как открывает/закрывает сообщения, смешение RU/EN, эмодзи, пунктуация, длина фраз, тон. **Сохранять дословную цитату-пример.**
- `[SOCIAL]` — как он общается **с живым человеком**: регистр под конкретного собеседника, кто первым пишет, как заходит в разговор и как его закрывает, как просит / отказывает / извиняется / благодарит, как реагирует на просьбу и на давление, где смягчает, где рубит, сколько себя открывает, как меняется тон от «свой» к «чужой». Обязательно указывать, **с кем** (имя/ник чата) и **какие отношения** (близкий, знакомый, деловой, продавец). Дословная цитата — обязательна.

Источник для `[INSIGHT]/[BEHAVIOR]/[VOICE]` — **реплики самого Димитри** из L0 (сессии хранятся вербатим), не мои ответы.
Источник для `[SOCIAL]` — его собственные сообщения (`out: true`) в экспортах Telegram (`type: telegram-export` в `11 — Архив/Телеграм чаты/`), в первую очередь в тех, что выгружены Шагом 0.5 этого прогона. Реплики собеседника — только контекст: без них не понять, на что он так отвечает, но фактом о Димитри они не являются.

Сохранять в `10 — Claude/Memory/L1 Atomic Memory/{YYYY-MM-DD}.md`

### Шаг 3 — Обновление Scene Blocks (L2)

Сцены: `obsidian-tools`, `personal-os-setup`, `psych-analysis`, `startup-ideas`, `dev-projects`, `life`

Структура сцены (с 2026-07-19):
- **Ядро** `10 — Claude/Memory/L2 Scene Blocks/L2 {сцена}.md` — тонкое: текущий срез (ключевые решения, открытые вопросы, связи) + раздел «## Журнал обновлений (по дням)» со ссылками.
- **Файлы-дни** `10 — Claude/Memory/L2 Scene Blocks/{сцена}/{сцена} {YYYY-MM-DD}.md` — сюда пишется содержимое обновления (frontmatter: `type: L2_update`, `scene`, `date`).

Порядок: прочитать **только ядро** → написать файл-день (если за сегодня уже есть — дописать в него) → добавить ссылку `- [[{сцена} {YYYY-MM-DD}]]` в журнал ядра → при необходимости поправить 1–2 строки текущего среза ядра. **Не дописывать содержимое обновлений в ядро и не читать старые файлы-дни.**

### Шаг 4 — Обновление Persona (L3)

Читать и обновлять `10 — Claude/Memory/L3 Persona/persona.md` из новых фактов — это **тонкое ядро** (идентичность, предпочтения, ограничения, решения, стиль, активные сцены).

Тяжёлые модули вынесены отдельно и в ядре представлены ссылками: `Психологический профиль.md`, `Паттерны поведения.md`. Обновлять модуль — только если новые факты реально меняют профиль/паттерны (точечным Edit, не переписыванием); целиком не читать — искать нужный фрагмент поиском.

### Шаг 4b — Идиолект и повадки (L3, гранулярно)

Отдельный профиль: **как Димитри думает, ведёт себя и пишет — вплоть до мелочей**.

Структура (с 2026-07-19):
- **Ядро** `10 — Claude/Memory/L3 Persona/Идиолект и повадки.md` — тонкий указатель: ссылки на архивные модули (`Идиолект/Идиолект — мысли и инсайты.md`, `…— поведение.md`, `…— как пишет.md`, `…— мелочи.md`) и раздел «## Файлы-дни».
- **Файлы-дни** `10 — Claude/Memory/L3 Persona/Идиолект/идиолект {YYYY-MM-DD}.md` — сюда писать новые наблюдения (frontmatter: `type: L3_idiolect_day`, `date`; внутри — те же 4 рубрики).

Порядок: **не читая архивных модулей**, из тегов `[INSIGHT]/[BEHAVIOR]/[VOICE]/[SOCIAL]` (Шаг 2) написать файл-день и добавить ссылку в раздел «Файлы-дни» ядра. Рубрики наблюдений:

- **Мысли и инсайты** — его собственные осознания/выводы/идеи-фикс, повторяющиеся темы. Каждый — с датой и дословной цитатой.
- **Поведение** — паттерны действий: как принимает решения, что делает под стрессом/при сомнении, прокрастинация, перепроверка, where он спорит vs соглашается, на что реагирует резко.
- **Идиолект (как пишет)** — характерные слова и обороты, сленг, мат, как открывает/закрывает сообщения, смешение RU/EN/других языков, эмодзи и пунктуация (мало/много, «...», капс), длина и ритм фраз, опечатки-маркеры, прямота vs смягчение.
- **Как общается с людьми** — из тега `[SOCIAL]`, по экспортам Telegram. Что писать: с кем и какие отношения; регистр и дистанция (тёплый / деловой / терсный / флиртующий); кто инициирует и кто закрывает разговор; чем открывает и чем заканчивает; как просит, отказывает, извиняется, благодарит, спорит; как реагирует на просьбу о деньгах/услуге и на давление; сколько о себе рассказывает; подстраивается ли под манеру собеседника (длина сообщений, смайлы, звукоподражания); отличие от рабочего регистра с агентами. Одна подрубрика на человека: `**{Имя чата}** ({какие отношения})` и под ней наблюдения с цитатами.
- **Мелочи** — любые повторяющиеся микро-привычки, не влезшие выше.

**Правила:**
- Только наблюдаемое в его репликах — **никаких домыслов**; каждый пункт подкреплять цитатой-примером и датой.
- Наблюдения по общению накапливаются в архивном модуле `Идиолект/Идиолект — как общается с людьми.md` (создать при первом наблюдении, дальше — только файлы-дни, как с остальными рубриками). Ядро `Идиолект и повадки.md` держит ссылку на модуль.
- Переписка с живыми людьми — чувствительный материал: в память идут **паттерны общения с цитатой-примером**, а не пересказ чужой личной жизни и не секреты собеседника. Если фрагмент нужен только как контекст — не выносить его в память.
- Повтор уже известного паттерна — просто зафиксировать в файле-дне с цитатой (дедупликацию против архива делает периодическая консолидация, не каждый прогон).
- Связывать с `[[persona]]` и релевантными заметками через `[[ ]]`.

### Шаг 4c — Журнал архитектурных решений (ADR)

Из **dev-сессий** (сцена `dev-projects` и любые сессии с решениями по коду, архитектуре, инфраструктуре, разобранными багами/инцидентами) извлечь **состоявшиеся решения** — не каждое обсуждение — и оформить каждое отдельной заметкой в `06 — Проекты/Журнал архитектурных решений/`:

- Имя файла: `{YYYY-MM-DD} — {суть решения}.md`. Одна заметка — одно решение.
- Frontmatter: `type: adr`, `date`, `project` (wiki-link, если привязано к проекту), `status: принято`, `tags` обязательно: `adr`, `dev`, тема (`микросервисы`/`база-данных`/`kafka`/`devops`/`инцидент`/…), проект (`isms`/…).
- Тело — **строго сплошным текстом**, как обычная заметка с мыслями: без списков, таблиц и заголовков-секций. Прозой: контекст и проблема → рассмотренные варианты → что выбрано и почему → цена/компромиссы → условия пересмотра. Связи `[[...]]` на проект и смежные решения.
- Новую заметку дописать в список «Записи» в `MOC — Журнал архитектурных решений.md`.
- Перед созданием проверить, нет ли уже заметки об этом решении (по MOC) — тогда обновить её (`status: пересмотрено` при смене решения), не дублировать.

### Шаг 5 — Семантический граф (L4)

L4 — ассоциативный слой памяти. После обновления L1–L3 пересобрать граф и зафиксировать новые скрытые связи.

```bash
VSEARCH="$HOME/Desktop/personal os/tools/obsidian/tools/obsidian_vsearch.py"

# 5.1 — переиндексировать заметки (новые/изменённые)
python3 "$VSEARCH" index

# 5.2 — перестроить граф
python3 "$VSEARCH" build_graph 0.55 8

# 5.3 — найти новые скрытые связи
python3 "$VSEARCH" brainstorm "" 20 0.72
```

Значимые связи (score > 0.75, разные разделы) записать в **файл-день** лога L4 (не в общий файл!):

```bash
# файл-день: создать или дописать сегодняшний
node ~/.claude/skills/obsidian/driver.mjs obsidian_append \
  '{"path":"10 — Claude/Memory/L4 Semantic Graph/Log/Graph Log {YYYY-MM-DD}.md","content":"## {YYYY-MM-DD} (memory-extractor)\n- [[note1]] ↔ [[note2]] (раздел1 ↔ раздел2, score)\n..."}'
# и добавить ссылку "- [[Graph Log {YYYY-MM-DD}]]" в индекс
#   10 — Claude/Memory/L4 Semantic Graph/Semantic Graph Log.md (если её там ещё нет)
```

`Semantic Graph Log.md` — теперь тонкий индекс со ссылками на файлы-дни; содержимое связей в него не писать и целиком старые файлы-дни не читать (контекст прошлых прогонов — только последний файл-день).

Граф-артефакт обновляется в `~/Desktop/personal os/tools/obsidian/tools/graph/graph.html`.
