# Социальный капитал

База личных контактов и связей: **SQLite** для машины и **карточки в Obsidian**
для человека. Одни и те же данные, две поверхности.

```
tools/social-capital/
  capital.py          — CLI (единственный инструмент)
  social_capital.db   — база (SQLite, WAL)
  graph/graph.html    — граф людей, организаций и связей
  contacts.csv        — выгрузка (по команде export-csv)

Органон/08 — Социальный капитал/
  MOC — 08 — Социальный капитал.md   — индекс по категориям + «пора написать»
  Контакты.base                       — таблица для плагина Bases
  Люди/{Имя}.md                       — карточка на человека
  _Шаблон — карточка контакта.md      — заготовка для ручного добавления
```

## Модель данных

| Таблица | Что хранит |
|---|---|
| `contacts` | человек: имя, категория, статус, работа, гео, адрес, день рождения, оценки (близость/доверие/влияние/ценность), знакомство, ритм касаний, сделка, заметка |
| `orgs` | организации (компания, вуз, сообщество) — куда привязан человек |
| `channels` | каналы связи: email, телефон, telegram, linkedin, github, сайт, vk, … (сколько угодно на человека) |
| `attrs` | интересы, навыки, теги, проекты |
| `relations` | связи человек↔человек: вид, сила 1–5, с какого времени |
| `interactions` | история касаний: дата, вид, суть, следующий шаг |
| `categories` | категории с цветом — поле деления и раскраска графа |

Категории по умолчанию: `family, friends, partners, clients, leads, colleagues,
mentors, community, service, inbox, other`.

### Подкатегории

Категории — дерево: у любой может быть подкатегория. Из коробки заведены
`Клиенты → Активные / Бывшие` и `Лиды → Тёплые / Холодные / По рекомендации`.

```bash
$PY capital.py category add leads-conf "С конференций" --parent leads
$PY capital.py category list                 # дерево со счётчиками и цветами
$PY capital.py set "Имя" "категория=Тёплые"  # достаточно имени подкатегории
$PY capital.py list --category leads         # срез включает все подкатегории
$PY capital.py category rm leads-conf --move-to leads
```

В карточке это два свойства — `категория` (корневая) и `подкатегория`, так что
в таблице Bases можно фильтровать и по группе, и по ветке. Достаточно вписать
новое значение в `подкатегория` прямо в Obsidian: `pull` заведёт её в базе сам,
привязав к указанной корневой категории.

В графе подкатегория — своя строка легенды и оттенок родительского цвета
(«Лиды» бирюзовые → «Тёплые» светлее той же гаммы), так что семья категорий
видна глазом. Свой цвет — `--color`.

## Частые команды

```bash
PY=/Library/Frameworks/Python.framework/Versions/3.13/bin/python3
cd "~/Desktop/personal os/tools/social-capital"

$PY capital.py add "Имя Фамилия" --category clients --org "Компания" \
    --role "CTO" --email a@b.com --tg @nick --city Тбилиси \
    --interests "ml,бег" "чем полезен=выход на инвесторов" "близость=3"

$PY capital.py set "Имя" "категория=Партнёры" "следующий контакт=2026-09-01"
$PY capital.py link "Имя" "Другое Имя" --kind "познакомил меня" --strength 4
$PY capital.py log "Имя" --kind встреча --summary "обсудили пилот" --next "прислать КП"

$PY capital.py list --category clients      # срез
$PY capital.py list --due                   # кому пора написать
$PY capital.py show "Имя"                   # досье целиком
$PY capital.py export-csv                   # плоская выгрузка (база клиентов)

$PY capital.py sync --pull                  # Obsidian ⇄ база, потом карточки
$PY capital.py sync --prune                 # + убрать карточки удалённых людей
$PY capital.py dedupe --dry                 # показать дубли, ничего не меняя
$PY capital.py graph                        # пересобрать граф связей
```

Правки в Obsidian и правки в базе не конфликтуют, если помнить направление:

* поправил карточку руками → `pull` (карточки → база);
* поправил через CLI → `sync` (база → карточки);
* `sync --pull` делает и то и другое разом — обычный рабочий вариант.

Синхронизация переписывает **frontmatter и авто-блок** карточки. Всё, что ниже
`<!-- /capital:auto -->`, — твоё, инструмент туда не лезет.

Переименовать человека — менять свойство `имя` (или `set "кто" имя=...`), а не
имя файла: файл карточки следующий `sync` переименует сам, свободный текст
переедет вместе с ним. Опознание идёт по `slug`, он не меняется.
В имени файла запрещённые символы (`/ : | # [ ]` из телеграм-ников) заменяются
на дефис — в базе имя остаётся как есть.

**Тёзки.** Одно имя — один файл, поэтому полные тёзки получают уточнение в
скобках: `Иванов Иван Иванович (МГУ)`, а если и организация совпала — по городу,
затем по slug. Раньше уточнения не было и тёзки затирали карточки друг друга:
в базе 6585 человек, а в Obsidian оказывалось 4908 файлов.

## Дубли

Массовые импорты плодят одного человека по разу на организацию: сайты филиалов
перечисляют руководство головного вуза, и ректор приезжает в базу 28 раз.

```bash
$PY capital.py dedupe --dry --show 20   # какие группы схлопнутся и кто останется
$PY capital.py dedupe                   # слить
$PY capital.py sync --prune             # раскатать и убрать осиротевшие карточки
```

Сливаются записи с **одинаковым именем** (регистр и `ё` не считаются) плюс
хотя бы одно совпадение: общий канал связи (почта, телефон, ник) **или** та же
организация. Тёзка в другой организации и с другой почтой остаётся отдельным
человеком — такие лучше свести руками.

Что происходит при слиянии: остаётся запись при головной организации (у филиалов
и колледжей в названии есть характерные слова), пустые поля дозаполняются из
остальных, каналы связи, теги, связи и история касаний переезжают к ней, а
прочие места работы сохраняются свойством `организации`. Организации из базы не
удаляются. Перед прогоном имеет смысл скопировать `social_capital.db`.

## Откуда берутся контакты

Ручной `add`, правка карточек в Obsidian и три импорта. Все импорты идемпотентны
и **не затирают ручные правки**: у существующего человека заполняются только
пустые поля и добавляются недостающие каналы связи. У всех есть `--dry`.

```bash
# Telegram — личные диалоги (боты и каналы отсеиваются)
$PY capital.py import-telegram --limit 600 --dry
$PY capital.py import-telegram --limit 600 --contacts-only   # только адресная книга

# vCard — Контакты macOS/iOS («Экспорт vCard…»), Google Contacts
$PY capital.py import-vcf ~/Downloads/Контакты.vcf --category inbox

# CSV — Google Contacts, LinkedIn (Connections.csv), выгрузка CRM, своя табличка
$PY capital.py import-csv ~/Downloads/Connections.csv --source linkedin --dry
```

Личные диалоги в Telegram лежат ниже каналов, поэтому `--limit` нужен большой.
Из vCard берутся имя, организация, должность, все email и телефоны, адрес,
день рождения, сайты, соцпрофили и заметка. В CSV колонки распознаются по
заголовку (`имя/name`, `организация/company`, `email`, `телефон/phone`, `город`,
`интересы`, `навыки`, `категория`, `подкатегория`, …) — незнакомые игнорируются;
`категория`/`подкатегория` из файла заводятся в базе автоматически.

Импортированные попадают в `inbox` («Неразобранное») — дальше разложить по
категориям через `set` или прямо в карточках.

## Граф связей

`capital.py graph` строит `graph/graph.html` — тот же движок и вид, что у графа
заметок и графа Zotero (`tools/obsidian/tools/obsidian_vsearch.py`).

* узлы — люди (цвет = категория) и организации-хабы (серые, `--no-orgs` убирает);
* рёбра — явная связь (сила 1–5), общая организация, общие интересы/навыки/теги,
  общий город (слабый штрих, сам по себе ребро не даёт);
* порог веса — `--thr` (по умолчанию 0.3);
* в правой панели узла — полное досье: каналы, интересы, обмен ценностью,
  история касаний и свободный текст карточки.

Слишком общий тег (больше 12 человек) в рёбра не идёт — иначе граф превращается
в кашу «все связаны со всеми».

## Mission Control

Раздел «Хранилище контекстов → Графы памяти» — карточка «Социальный капитал»:
счётчики, кнопки «синхр. + граф» и «только граф», граф во встроенном фрейме.
API: `GET /api/capital`, `GET /capital/graph`, `POST /api/capital/rebuild`
(`{"sync": true}` — сначала прогнать `sync --pull`).

## Таблица в Obsidian (Bases)

`Контакты.base` — виды «Все контакты», «По категориям», «Клиенты и лиды»,
«Пора написать». Файл перезаписывается при `sync`, поэтому свои виды лучше
заводить отдельным `.base`, а не править этот.

Свойства карточек — русскими именами (`категория`, `организация`, `должность`,
`город`, `email`, `телефон`, `интересы`, `близость`, `последний контакт`, …),
поэтому таблица читается и без словаря.
