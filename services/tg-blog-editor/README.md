# tg-blog-editor — бот-редактор блога @digit_code

Наследник проекта **Feed-Conveyor**: человек-в-контуре публикация. Ничего не уходит
в канал, пока ты не нажал ✅. Формат поста — стиль канала (3 абзаца: суть → цитата
→ вывод).

Два источника постов:
1. **Лента новостей** (`radar.db`) — авто-рекомендации каждый день + команда `/draft`.
2. **Твои источники** — кидаешь боту в личку ссылку/пост, он собирает черновик.

## Источники от тебя (кинул в чат → получил черновик)

Просто отправь боту в личку — он определит тип, обработает **в фоне и параллельно**
(можно кидать несколько подряд) и пришлёт карточку-черновик с кнопками:

| Что прислать | Как обрабатывается |
|--------------|--------------------|
| 🎬 ссылка на YouTube | `yt-dlp` тянет субтитры (ru→en) → LLM пишет пост |
| 📰 ссылка на статью | `urllib`+`BeautifulSoup` извлекают текст → LLM |
| 💬 пересланный TG-пост | берётся текст поста → LLM |
| 📝 произвольный текст | используется как есть → LLM |

Извлечение + генерация — в воркере `process_source.py` (фреймворочный питон:
yt-dlp, bs4, claude-local-api). Бот вызывает его в фоновой задаче, поэтому
несколько источников обрабатываются одновременно.

> **NotebookLM:** глубокий разбор через NotebookLM — опциональный путь на будущее.
> Сейчас не подключён: нужен CLI `nlm` (`uv tool install notebooklm-mcp-cli`) +
> Google-авторизация. Для одной ссылки быстрее и надёжнее путь yt-dlp/веб-парсер
> выше; NotebookLM имеет смысл для ресёрча по многим видео сразу.

## Как работает

```
radar.db (новости)
   │  radar.py draft-posts → JSON {text, url}
   ▼
bot.py enqueue  ──►  личка владельца: карточки-черновики с кнопками
   │                    ✅ Опубликовать · 🔄 Перегенерировать · ✏️ Править · ⏭ Пропустить
   │                         │ ✅ → бот публикует в @digit_code
   │                         │ (через AUTO_PUBLISH_HOURS без решения → авто-публикация)
   ▼
bot.py run  ──►  long-polling: ловит нажатия кнопок и команды
```

## Команды бота (в личке, только владелец)

| Команда | Что делает |
|---------|-----------|
| `/start` | приветствие и справка |
| `/draft [N]` | собрать N черновиков на ревью (по умолчанию `DRAFTS_PER_RUN`) |
| `/pending` | показать неразобранные черновики |

## Кнопки под черновиком

`✅ Опубликовать` · `🔄 Ещё вариант` · `✏️ Править` · `⏭ Пропустить`

- **🔄 Ещё вариант** — генерирует альтернативу и добавляет её к черновику. Для
  новостного черновика берётся ДРУГАЯ новость (исключая уже показанные); для
  черновика из источника — повторная генерация по тому же источнику.
- **◀️ N/K ▶️** — когда вариантов несколько, стрелки листают их. `✅` публикует
  тот вариант, что сейчас показан.
- **✏️ Править** — пришли свой текст, заменит текущий вариант.

## Дедуп новостей

Рекомендации не повторяют истории, которые уже **опубликованы** или **отклонены**
(`⏭`): их url исключаются при генерации. Если свежих историй не хватает, бот сам
догоняет парсер новостей (`radar.py ingest`) и берёт другие.

## Точки входа (CLI)

| Команда | Кто вызывает | Что делает |
|---------|--------------|-----------|
| `bot.py run` | супервизор `pos` | long-polling бот (кнопки + команды) |
| `bot.py enqueue --n 5` | крон `digitcode-digest` (10:00) | сгенерить 5 черновиков и прислать на ревью |
| `bot.py autopublish` | крон `blog-autopublish` (ежечасно) | опубликовать черновики старше `AUTO_PUBLISH_HOURS` |

## Настройка (.env)

```
BOT_TOKEN=...            # из @BotFather
OWNER_ID=934458920      # кому слать черновики и кто управляет
CHANNEL=@digit_code     # куда публиковать
AUTO_PUBLISH_HOURS=6    # таймаут авто-публикации
DRAFTS_PER_RUN=5        # сколько постов за прогон
```

## Требования к запуску

1. Бот должен быть **администратором** канала `@digit_code` с правом постинга
   (публикует сам бот).
2. Владелец должен один раз нажать **/start** в личке бота
   (иначе Telegram не даёт боту написать первым).

## Очередь

Состояние — `data/queue.db` (SQLite): `pending | published | skipped`, с привязкой к
карточке (chat_id/message_id) для редактирования сообщения после решения.
