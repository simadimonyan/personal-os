# hh-autoapply — авто-отклик на hh.ru

Ищет вакансии, отсеивает неподходящие, пишет персональное сопроводительное и
откликается. Запускается кроном 3×/день (`hh-autoapply-am/day/eve`), отдельная
задача `hh-responses` следит за ответами работодателей.

## Конвейер

```
авторизация → резюме → поиск (пагинация)
   → жёсткий фильтр по названию        (title_keywords / title_exclude)
   → загрузка описаний вакансий        (hh_get_vacancy)
   → смысловой отсев моделью 0–10      (analyzer.screen_batch, батчами)
   → персональное письмо под вакансию  (analyzer.cover_letter)
   → отклик + запись в history.db
```

Смысловой слой необязателен. Если `claude-local-api` недоступен, `llm.enabled=false`
или запуск с `--no-llm` — работает как раньше: фильтр названий + статичное письмо
из `cover.txt`. Модель никогда не роняет прогон: любой её сбой откатывается на fallback.

## Файлы

| Файл | Назначение |
|------|-----------|
| `autoapply.py` | Основной сценарий откликов |
| `responses.py` | Монитор ответов HR: приглашения/отказы с прошлого прогона |
| `analyzer.py` | Оценка вакансий и генерация писем через модель |
| `llm.py` | Клиент к `claude-local-api` (unix-сокет), с мягкой деградацией |
| `history.py` | SQLite-история (`history.db`) + миграция из `applied.json` |
| `hhdriver.py` | Общая обвязка вокруг node-драйвера hh + конфиг |
| `config.json` | Поисковые фильтры и настройки LLM |
| `cover.txt` | Статичное письмо — fallback и образец тона для модели |
| `profile.txt` | Кэш профиля кандидата для промптов (создаётся сам, можно править руками) |

## Запуск

```bash
python3 autoapply.py              # боевой прогон
python3 autoapply.py --dry        # поиск + оценка, без откликов
python3 autoapply.py --explain    # показать оценки и письма целиком
python3 autoapply.py --no-llm     # принудительно по старой схеме
python3 responses.py              # изменения по откликам
python3 responses.py --all        # весь список откликов
python3 history.py                # состояние базы
python3 analyzer.py               # доступна ли модель, какой профиль подставляется
```

## Управление из Telegram — `/hh`

Пульт живёт в личном ассистенте (`services/tg-psych-bot`, команда `/hh`):
статистика, разовый прогон, пауза, порог отбора и правки стиля писем — без
захода в терминал. Приглашения от работодателей бот присылает сам.

Разделение труда: браузерную работу делает крон, бот только читает `history.db`
и правит `config.json`. Поэтому бот не зависит от того, жив ли сейчас hh, и
не блокируется на медленных страницах. Детали — в README бота.

`llm.letter_notes` в конфиге — как раз те правки, что надиктованы из Telegram;
они подставляются в промпт письма последними и перебивают общие правила.

## Настройка отбора — `config.json`

```jsonc
"llm": {
  "enabled": true,
  "model": "haiku",          // модель claude-local-api
  "min_score": 6,            // порог прохождения, 0–10
  "batch_size": 8,           // вакансий на один запрос к модели
  "max_screened": 25,        // сколько кандидатов оцениваем за прогон
  "personal_letter": true,   // писать письмо под каждую вакансию
  "criteria": ["..."]        // требования на человеческом языке
}
```

Порог подбирать по `--dry --explain`: там видно оценку и обоснование по каждой
вакансии, и понятно, режет модель лишнее или пропускает.

## history.db

Таблица `applied` — что тронули: название, компания, оценка с обоснованием,
отправленное письмо, исход (`applied` / `already` / `skip` / `rejected_by_llm` /
`legacy` для 226 записей, перенесённых из `applied.json`).
Таблица `negotiations` — последний увиденный статус каждого отклика; по разнице
с ним `responses.py` понимает, что появилось нового.

`applied.json` продолжает обновляться — его читает mission-control.

## Грабли

- **VPN ломает hh.** Под VPN сайт отдаёт заглушку «VPN мешает работе сайта» с кодом
  200 или роняет `page.goto` по таймауту — в логах крона это выглядит как «вакансий
  не найдено». `analyzer` такие заглушки распознаёт и не кэширует их в `profile.txt`,
  но сам поиск в это время всё равно пустой. Симптом — `просмотрено 0` в отчёте.
- **Файлы должны принадлежать пользователю.** Крон и сервисы работают не от root;
  если `history.db` создан из root-шелла, прогон упадёт на записи (EPERM).
- **Модель отвечает ~9с на запрос.** Поэтому оценка идёт батчами, а не по одной
  вакансии: 25 поштучных вызовов — это 4 лишних минуты на прогон.

## Родословная

Смысловой слой навеян [fikstt2/hh-ai-agent](https://github.com/fikstt2/hh-ai-agent)
(LLM-фильтрация по описанию, генерация писем, БД истории, мониторинг ответов HR).
Переложено на инфраструктуру Personal OS: вместо Ollama — `claude-local-api`,
вместо своего Playwright-клиента — общий `tools/hh/driver.mjs`, вместо
собственного Telegram-бота — штатные приёмники крона.
