# Personal OS — сервисы

Единый автономный слой Personal OS: одна точка входа поднимает и стережёт все
фоновые сервисы, пока включён ноутбук. Ничего не нужно запускать вручную по частям.

## Одна точка входа — `pos.py`

```bash
cd ~/Desktop/personal\ os/services

./pos.py up        # установить launchd-агент и запустить ВСЁ (и при логине)
./pos.py status    # что сейчас живо: супервизор + каждый сервис
./pos.py down      # остановить всё и убрать из автозапуска
./pos.py restart   # перечитать services.json и перезапустить
./pos.py logs cron # хвост лога сервиса (pos | cron | claude-local-api | ...)
```

`pos.py` — это **процесс-супервизор**: один launchd-агент `com.dimitri.pos` запускает
супервизор, а он поднимает дочерние сервисы, перезапускает упавшие (с backoff) и
пишет состояние в `pos_state.json`. Список сервисов — в `services.json`.

```
launchd (com.dimitri.pos)
   └── pos.py (супервизор)
        ├── claude-local-api   — локальный Claude через Unix-сокет
        ├── cron               — планировщик задач …
        │     └── radar ingest, дайджесты, рассылки (по расписанию, с догонкой)
        └── tg-psych-bot       — (опционально; по умолчанию через свой launchd)
```

## Сервисы

| Папка | Что | Запуск |
|-------|-----|--------|
| [`claude-local-api-main`](claude-local-api-main) | Локальный Claude (Unix-сокет `/tmp/claude_api.sock`) | под супервизором |
| [`cron`](cron) | Планировщик задач: расписания, догонка пропущенного, учёт сети | под супервизором |
| [`radar`](radar) | Агрегатор инфополя: RSS+TG → векторная база (ONNX) + дайджест трендов | через cron |
| [`tg-psych-bot`](tg-psych-bot) | Telegram-бот психотрекинга | свой launchd (или включить в `services.json`) |
| [`mission-control`](mission-control) | Веб-пульт всей системы: статус сервисов/крона + кнопки управления (127.0.0.1:8787) | под супервизором |

## Добавить новый сервис

1. Дописать запись в `services.json` (`name`, `cmd`, `cwd`, `enabled`, `autorestart`).
2. `./pos.py restart` — супервизор подхватит.

Разовые/периодические задачи (не постоянные демоны) добавляются не сюда, а в
планировщик: `cd cron && ./cronctl.py add ...`.

## Автономность

- Всё живёт, пока включён ноутбук; при логине поднимается само.
- Упавший сервис перезапускается супервизором.
- Сетевые задачи переживают офлайн: при отсутствии интернета откладываются и
  выполняются приоритетно, когда связь вернётся (см. [cron](cron/README.md)).
- Нужен интерпретатор `/Library/Frameworks/Python.framework/Versions/3.13/bin/python3`
  (в нём onnxruntime/tokenizers для векторизации radar).
